# Using Meari in a Rust app

This guide is for Rust developers who want to put a Meari UI inside their own application. It explains where your code ends and Meari begins, and it is upfront about what is not supported yet.

## The idea in one paragraph

Meari reads a UI declaration, written as a bounded subset of TSX or as plain Rust, and turns it into a typed component. That component is data: Meari never runs JavaScript, React or a browser reconciler. Your product logic stays in your Rust code. The UI layer holds the declaration, the design tokens and assets, and small adapters that turn UI events into calls into your application.

## Start from a working example

The quickest way in is a fixture that already passes the tests, then change it step by step. In the repository, [mixed-hooks.tsx](https://github.com/modootoday/meari/blob/main/crates/meari/fixtures/mixed-hooks.tsx) is the smallest path through HTML, `useId`, `useState` and a click, and [state-counter.tsx](https://github.com/modootoday/meari/blob/main/crates/meari/fixtures/state-counter.tsx) shows buttons and inputs with state, disabled controls and inputs that keep what you typed.

When something does not convert, keep the original snippet. A small failing example is the most useful thing to bring to an issue.

## Converting between TSX and Rust

Three functions cover conversion: `meari::parse(source, Language::Tsx)`, `meari::emit(&component, Language::Rust)` and `meari::convert(source, from, to)`. The output carries the generated code, a mapping between source and generated byte ranges, and a schema version. Read that version rather than assuming one.

When a construct is outside the supported profile you get a diagnostic with a code, a message and the exact span. Meari does not quietly replace what it cannot handle.

The same converter is available from the shell:

```sh
meari convert tsx-to-rust --json < card.tsx
meari convert rust-to-tsx --json < card.rs
```

Generated Rust imports `meari::runtime`. It is meant to be mounted by a document host, not run as a program of its own.

## Showing it in a native window

`meari-native` owns a persistent document. You create it from a component, your CSS and a viewport, then dispatch actions such as activating a button. State changes, focus and the accessibility tree all live in that document, so your app reads what happened instead of re-rendering everything.

With the `window` feature, a native window driver can run inside your own winit event loop, or show a window on its own for simple cases. Callbacks into your application are queued: Meari admits an event, hands it to you after it has finished touching the document, and you update the props in one synchronous step. This keeps your application code out of the renderer's way and makes retries and closing a window predictable.

Apps that draw their own title bar can call `WindowAction::BeginResize` to let the OS resize the window from an edge or corner. Where the OS refuses, as on macOS, it returns `ActionError::Unsupported` so you can fall back.

## Showing it in the browser

Build `meari` with the `wasm` feature for `wasm32` and mount the same component with `WebDocument` into a container element. Keep the returned mount alive; dropping or closing it removes its listeners. Buttons, inputs and the supported HTML tags map directly. Richer shadcn recipes need explicit adapters and are rejected until they exist, so plain HTML with your own CSS is a good place to start.

## Styling

Document hosts take CSS text. Tailwind classes work once you hand Meari the compiled CSS; no JavaScript packages are resolved at run time. Use your project's shared CSS and token file and keep SVG assets in your own source tree.

## Lists, state and props

Props can be strings, booleans and typed arrays, and empty arrays keep their element type. A keyed `.map()` over a string array becomes a repeated row in both targets, and each keyed row keeps its own state, focus and typed input when rows move, appear or disappear. Use string keys that are unique within the list.

## What is not supported yet

Meari tells you plainly where its edges are:

- General React hooks such as `useReducer`, refs, memo and effects, arbitrary function bodies and full React semantics.
- Complete CSS parity with the browser and the full set of shadcn widgets on every target.
- A finished Native+Web builder and coordinated hot reload of both running hosts.
- Full acceptance on real operating systems for keyboard input methods, screen readers and suspend.

For API details see [docs.rs](https://docs.rs/meari), and for what is checked automatically see [How Meari is tested](verification.md).
