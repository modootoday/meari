# Consuming Meari from a Rust application

Meari accepts bounded TSX UI declarations and canonical Rust construction code. Parsing TSX does not run a JavaScript module, npm React, arbitrary component functions or a browser React reconciler. Keep product use cases and policies in the consuming Rust SDK; keep UI declaration, tokens/assets and event-to-use-case adapters in presentation modules.

## Start with existing fixtures

Use [mixed-hooks.tsx](../packages/meari/fixtures/mixed-hooks.tsx) for the smallest shared HTML/useId/useState/click path, or [state-counter.tsx](../packages/meari/fixtures/state-counter.tsx) for tested Button/Input state, disabled and uncontrolled input retention. Preserve a failing original snippet when extending support.

Supported declarations include exported components with typed string/bool/Array and Action/Text callback props, relative named component graphs, a returned element tree, boolean prop predicates, bounded primitive useState slots, useId and ordered mixed hooks. The keyed string-array map profile below has Core, Native and actual browser execution coverage. Scalar setter expressions and functional string/number/bool updaters have distinct captured/current-state semantics. General package/module execution, arbitrary function bodies, conditions, unrestricted maps, useReducer/ref/memo/callback/effects and full React semantics are unfinished. A recognized shadcn import/component name does not prove its renderer/props/interactions exist on every target.

The text/checked source fixture [input-state.tsx](../packages/meari/fixtures/input-state.tsx) has executed Core conversion/dispatch coverage. Native regression coverage now checks actual text/checkbox properties and typed state, retained text focus/accessibility, engine keyboard and AccessKit SetValue. Web currently rejects typed source input. Controlled HMR, recovery-failure poison, composition/selection and actual OS acceptance need further scenarios; this is not a complete product editor.

## Conversion and diagnostics

Rust entry points are `meari::parse(source, Language::Tsx)`, `meari::emit(&component, Language::Rust)` and `meari::convert(source, from, to)`. `Output` contains schema_version, code, source/generated byte-span mappings and design_system capabilities. Read the returned version instead of assuming every output is schema2. Errors retain code/message/span; report the original snippet and bytes rather than replacing unsupported expressions with constants.

The `meari-cli tsx-to-rust --json` and `meari-cli rust-to-tsx --json` commands read source on stdin and return Output JSON. Failure returns Diagnostic JSON on stderr and exit1. The CLI and Rust APIs share the converter. Generated Rust imports `meari::runtime`; stateful code requires a StateContext snapshot. Use the parsed Component with a document host rather than treating generated output as a standalone executable.

## Native and Web ownership

Native: `meari_native::infrastructure::document::InteractiveDocument::new(component, css, viewport)` owns the persistent renderer; `from_application` retains the original build definition. `dispatch(Action::Activate { path })` applies a registered source setter or widget action. `component_state` and the accessibility adapter expose semantic evidence. Source paths identify elements in the current tree; they are not product command names.

Web: compile `meari` with feature `wasm` for wasm32. `meari::infrastructure::web_document::WebDocument::mount(container, &component, &props, css, document_id, epoch)` returns an owned mount. Retain that object; Drop/close remove its listeners and wrapper. `mount_application` also attaches host observations. Current Web component mapping includes Button→button, Input→input and supported HTML tags; Button recipes such as variant/size/asChild and composite shadcn widgets need explicit adapters and are rejected. Plain HTML with explicit CSS is a useful tested consumer starting point, not the final design-profile acceptance boundary.

Browser JS exports `meari::wasm::convert_source` and `prepare_native_plan` are conversion/planning transports. They do not by themselves mount a React application. Prefer the generated Rust Web application or a Rust WebDocument host. Core source onClick can represent a typed state update or an explicit Action host intent; scoped Rust host-intent queues have execution coverage in both document adapters. Keep product operations in registered Rust adapters.

## Styles and tokens

Document hosts accept CSS text; Tailwind class strings require compiled CSS. They do not invoke npm or resolve @/ imports at runtime. `StylesheetProject` retains original CSS/Tailwind entry/files with normalized relative paths. Builder `AppConfiguration` specifies stylesheet mode/entry/bridge_theme and Theme. CSS mode uses bridge_theme=false. Tailwind bridge injection requires all validated semantic light/dark tokens; an empty default Theme is not a complete palette. Native component recipes do not automatically create matching Web recipes.

Use the consuming project's approved shared CSS/token file and source-owned SVG assets. Arbitrary inline SVG/source asset modules and all Icon render paths are not established Web support. Keep any adapter gap explicit and hand off the smallest source/asset reproduction.

## Build and run

`meari_builder::application::build::execute(BuildRequest)` and `meari-builder build REQUEST.json` load a declared ProjectRequest file inventory, AppConfiguration and trusted host tool registrations. The current canonical integration example is [real_apps.rs](../packages/meari-builder/tests/real_apps.rs); it constructs a TSX/CSS/app.json project and Native/Web targets. Register absolute cargo/rustc/Trunk/bindgen paths with verified hashes outside editable source. Existing tools/caches can be reused; installing tools and heavy builds need the host's resource coordination.

Generated Native apps use the same factory for GUI and `--snapshot --action NODE_PATH`. Generated Web apps retain WebDocument; Trunk produces the WASM loader. `meari-builder serve STORE_ROOT PORT SECONDS` serves a verified current Web publication on loopback. Actual Native+Web build and Native headless state/render/accessibility have execution evidence, while the latest Web input/host/HMR scenarios still need actual browser acceptance. A published build is not proof that both running hosts acknowledged a frame.

Retained source/application prepare/commit/rollback APIs and their limits are described in [runtime-lifecycle.md](runtime-lifecycle.md). Browser editor transport and synchronized Native/Web HMR remain integration work.

## Report a consumer blocker

Provide the original minimal TSX, props JSON, CSS/token/asset inputs, target and exact Diagnostic, plus intended interaction and SDK use-case boundary. Distinguish parse/convert failure from DOM preparation, build, runtime event and appearance failures. Meari owns shared grammar/runtime/adapter changes; the consuming presentation owns its UI source/design/assets. Revalidate the same preserved input after the library fix, including render, interaction and accessibility evidence. Do not mark a converted but inert UI as supported.


## Source module API in development

The source module API adds `parse_module_graph(&entry, &sources)`, where entry is a portable `BuildPath` and sources is a declared `BTreeMap<BuildPath, String>`. It preserves each module's hash, component and local import bindings. Missing files/exports return `ModuleDiagnostic { file, diagnostic }`. The original single-source parse/convert APIs retain their strict import policy. Core graph, Native document and builder contract regressions pass with workspace/WASM strict Clippy. Generated Native/Web graph builds and Native CLI state/raster/accessibility have separate execution evidence. Current document and keyed-repeat cases also pass in the desktop in-app browser; consuming-product acceptance and rebuilding every generated app with the expanded profile remain further work.

`application::source_modules::ModuleProgram::mount` owns a separate StateProgram for each component call instance. `project` exposes the rendered component, source origins/calls and per-instance state snapshots; `activate`, `input` and `update_props` stage changes before publishing a new projection. Renderer paths refer to the current projection and its instance binding. This API does not run JavaScript modules.

| Stage | Current source boundary |
| --- | --- |
| Relative named TSX imports | Declared inventory only; exact path or unambiguous `.tsx`/`index.tsx`, with original import ranges |
| Props | Required string/bool/typed Array/callback and bounded ReactNode values; child props evaluated from the parent projection |
| State/useId | Separate programs and scoped IDs per call instance; parent props update retains compatible child state |
| Projection | Intrinsic renderer tree plus retained declaration/call/instance origin; source imports are preserved in the graph |
| Native/Web documents | Native graph DOM/event/input/props and CPU raster have execution coverage. Web click/callback/props and keyed DOM transactions have actual browser coverage; typed Web state-setter inputs remain rejected |
| Builder and source output | Actual graph EXE/WASM builds, common publication and Native CLI independent child state/raster/accessibility/last-good checks pass. Original per-file copies and mappings are retained; Rust module roundtrip output remains unfinished |
| Slots/callbacks/lists/HMR | Action/Text callbacks, keyed string maps and bounded named node slots/children have document coverage. General ReactNode/iterables, unrestricted maps/capture, Boolean callbacks and graph HMR remain unfinished |

A successful graph parse or Core projection is not a successful rendered product screen. Keep product sources unchanged when reporting gaps and verify the same source inventory through the actual target document and build after adapter changes.

### Typed node slots

Required `ReactNode` props accept JSX elements/fragments, named forwarding and explicit `null` as an empty slot. Typed local component `children` can contain mixed text/elements. Missing props differ from empty props. Source slots retain caller state, useId, callbacks and source origins. Consuming the same subtree twice is rejected. Node arrays and general React execution remain unsupported. Conversion uses schema10 when node slots are present.

Runtime Rust hosts issue opaque slots through `ModuleProgram::mount_with_node_slots(graph, document, epoch, prepare)` and the prepare closure's `NodeSlotFactory::component(key, reference, props)`. Providers must already exist in the declared graph. For later updates use `program.node_slots().component(...)`, Native `InteractiveDocument::node_slot(...)` or Web `WebDocument::node_slot(...)`. Pass the returned `Value` in the exact root props; use `Value::NodeSlot(NodeSlot::Empty)` for an explicit empty slot. Deserialized authoring `NodeSlot::Content` grants no runtime authority and is rejected there.

Mount the prepared program with Native `from_module_program` or Web `mount_module_program(container, program, css, document_id, epoch)`. Same placement/key/component updates retain state and DOM identity. Changing the key/component replaces that subtree. Foreign, retired or unused older-generation slots are rejected without replacing the last good projection. Callback documents still require the existing atomic callback export update API. Do not serialize runtime slots or treat a program clone as an independent document owner.

Core conversion/projection, Native DOM/raster/accessibility semantics and an actual desktop in-app browser test cover this bounded profile. Browser evidence includes retained input value/focus/state, replacement node detachment and stale-event rejection; full product screens, OS input and screen-reader acceptance require separate verification.



Native graph hosts use `InteractiveDocument::from_module_program(program, css, viewport)`, `module_projection` and `update_module_props`. Existing document activation and typed input routes dispatch to the owning module instance. Web Rust hosts use `WebDocument::mount_modules(container, graph, props, css, document_id, epoch)`, retain the owned mount, and read `module_snapshot` or update props with `update_module_props`. Application hosts can use `ModuleApplicationDefinition` with Native `from_module_application` or Web `mount_module_application`. `BuildBundle::module_application_definition` validates the module inventory against its build manifest. Single-source application/HMR loaders reject graph bundles; coordinated graph HMR remains unfinished. Builder asset integration, actual browser execution and consumer UI acceptance remain pending.

## Declared resources in development

`domain::assets::AssetManifest` describes original source paths, content hashes, lengths, roles, MIME types and license metadata. `application::assets::VerifiedAssets::new` verifies the exact blob inventory and shares immutable bytes. This verifies integrity; media decoding and embedded-reference handling belong to the host adapter.

`meari_native::infrastructure::stylesheet_assets::rewrite` resolves each original stylesheet's local resource URLs against that inventory and returns a rewritten project with original/generated URL spans. Compile the returned stylesheet project before passing CSS to the renderer. Imports remain with the project stylesheet compiler. Query suffixes are preserved; encoded paths, fragments, data URLs and remote URLs currently produce explicit diagnostics.

Native hosts can pass `VerifiedAssets` to `InteractiveDocument::new_with_assets`, `from_application_with_assets`, `from_module_program_with_assets` or `from_module_application_with_assets`. Direct document tests execute `new_with_assets` and `from_module_program_with_assets`, including real SVG pixels, font byte delivery, image accessibility and failed-update preservation. The ordinary constructors require an explicit asset provider for resource elements. `renderer.asset_report()` distinguishes delivered bytes and rejected requests; it does not certify complete font shaping or browser parity.

The builder now assembles declared Icon/Font/Image inputs, rewrites original per-file CSS URLs and static HTML src/poster URLs, embeds Native resources and copies Web resources into the static bundle. `BuildBundle::verified_assets` checks deployed resource bytes against the original input inventory. Explicit Native/Web app builds verify identical SVG bytes and real Native background/image pixels. The Native paint implementation is pinned locally in `packages/meari-paint`; generated Native Cargo projects patch registry paint dependencies to the same source.

Actual browser delivery, the original consumer UI's complete CSS/fonts/SVGs, dynamic source URLs and compressed Native fonts remain unfinished. SVGZ and embedded external SVG resources require further adapters. Offscreen CPU paint reports checked tiling failures; the window shell's checked-present error handling and real GL validation remain separate work.

`application::host_callbacks::HostCallbacks` provides scoped opaque Action/Text bindings to the existing PluginRegistry. The host owns payload construction and local draft intents; a text edit is not automatically an SDK save.

Complete Component parsing, Rust/TSX emission and generated Rust execution now cover `() => void`, `(value: string) => void`, explicit callback invocation/currentTarget.value, module callback forwarding and boolean prop negation. See the fixed consumer snapshots [host-callback-review.tsx](../packages/meari/fixtures/host-callback-review.tsx) and [host-callback-convert.tsx](../packages/meari/fixtures/host-callback-convert.tsx). Extended output uses schema6. Generated Rust uses typed `ActionCallback`/`TextCallback` references and retains React prop spelling.

Host props supply `Value::CallbackReference(CallbackReference { binding, signature })`; this serializable identity grants no dispatch authority. `binding::bind` checks signatures. `StateProjection::callbacks` and `ModuleProjection::callback_bindings()` retain typed intent inventories separately from DOM attributes, with module origins/instances retained. Emit the original authoring Component rather than a bound runtime projection.

Typed boolean props support nested `!`, `&&` and `||` predicates. Validation retains the offending expression's source range, binding uses short-circuit evaluation, and generated Rust/TSX preserve grouping. Predicate output uses schema7; existing callback/simple-negation output remains schema6. Focused Core/generated-Rust and Native truth-table tests pass, alongside WASM typechecking.

`HostCallbacks::export_bindings()` returns a document-owned `CallbackBindings` export with `scope`, typed `resolve`, `invalidate` and Drop revocation. Exported queued handles expire when that document lease closes; the registry still owns ticket cancellation/drain.

Native hosts can mount an already bound module program with `InteractiveDocument::from_module_program_with_callbacks(program, css, viewport, assets, source_generation, export_factory)`. The factory receives the actual mounted root `PluginScope` and returns the document's export. Retain the callback owner and the single plugin registry in the host. A failed constructor drops its export; the host must clean up any registry or product session it created in its factory.

After each normalized event, `drain_callbacks()` returns `PendingCallback { handle, invocation }` without borrowing the registry. Dispatch `invocation.arguments` through the retained callback owner and registry, return that mutable borrow, then process local draft/application results. Text edits are deferred typed intents, not implicit SDK saves. Real Native keyboard and AccessKit actions execute the same admission and queue path.

Use `update_module_props_with_callbacks(props, new_export)` for controlled updates. It stages props, bindings and retained shape before patching. Failed preflight drops the new export and leaves the old document/lease usable. Successful replacement drops the old export, invalidating even previously drained handles. Ordinary `update_module_props` rejects callback documents. `close_callbacks()` or document Drop revokes the export; cancel/drain already-started plugin tickets separately through their registry owner. Do not invalidate the old callback owner before an update succeeds.

The bounded queue and lease policy now live in Core `DocumentCallbacks`; Native adds node admission around that same queue. `PendingCallback` remains available from Native infrastructure. Focused Native tests execute the two fixed original TSX snapshots, deferred single-registry dispatch, textarea values/labels, disabled guards, failed-update preservation and stale handles. Default constructors still reject callbacks without a dispatcher.

The WASM adapter adds `WebDocument::mount_module_program_with_callbacks(container, program, css, (document_id, epoch), source_generation, export_factory)`, `callback_scope`, `drain_callbacks`, `update_module_props_with_callbacks` and `close_callbacks`. Rust input/click listeners check the owned current target and live control/CSS guards before using the shared queue. Controlled textarea/input properties update alongside retained DOM nodes. Both original-source browser cases pass in the desktop in-app browser, covering synthetic input/click, controlled values, retained nodes, deferred dispatch and export replacement/revocation. Web state-setter input listeners still return a separate unsupported-adapter diagnostic.

Native and Builder explicitly identify their owning workspace in their package manifests. Offline locked metadata also resolves the Native crate from the external consumer workspace. Consumers do not need to copy Meari's workspace dependency definitions.

Generated callback host factories and graph HMR remain unfinished. The new array/repeat profile still needs consuming-product SDK and GUI acceptance; scalar consumer proofs remain separate. These focused checks do not establish complete React execution or full widget/browser parity.

## Native document ownership and host turns

`meari_native::infrastructure::native_host::{NativeDocumentHandle, NativeHostRuntime, NativeWindowHost}` provides a UI-thread host port. Keep the single consumer registry/session/SDK inside your `NativeWindowHost`; neither the host nor its error/checkpoint types need `Send`. Construct the handle from the mounted document and its actual source generation, then retain `Rc<RefCell<NativeHostRuntime<H>>>`.

With feature `window`, `window::NativeWindowDriver::attach(&event_loop, runtime, options)` uses the caller's pinned winit loop. Delegate its `ApplicationHandler` methods from the caller's handler. `show_with_runtime(runtime, options)` is the standalone convenience. Existing `show` accepts callback-free documents; callback documents require the injected host. This CPU window port does not import an eframe loop or GL context.

`admit_callback` borrows an intent and returns `Accepted`, `Capacity` or `Rejected`. Admission must not execute SDK mutations. The runtime retains the unadmitted suffix; the consumer executes its admitted queue in `after_dispatch`, outside document/renderer guards. Resume on completion through `wake_handle().wake()`. Accepted SDK work is not automatically replayed. Pending suffixes block new input/reprojection until admission completes.

Apply staged props and callback exports synchronously through `handle.try_reproject(&turn.stamp, closure)`, then return its `HostCommitReceipt` in `HostEffects`. The driver validates the receipt and requests redraw; it does not apply the props a second time. Document stamps, input generations and SDK expected revisions are distinct. The closure must use the existing staged document update contract; this is not a rollback mechanism for arbitrary consumer mutations.

Close callbacks are revoked before consumer cleanup. Return a typed `CloseDecision` checkpoint to preserve pending/failed cleanup steps. The driver keeps the document/window until cleanup completes and then releases its resources. Drop is forced/incomplete and does not execute consumer SDK cleanup. `last_submission()` reports checked renderer submission, not OS compositor acknowledgement. Historical diagnostics are available through `presentation_errors()` and typed host errors through the retained runtime.

See the [thin consumer tests](../packages/meari-native/tests/source_callbacks/host_runtime.rs) and [actual OS driver smoke](../packages/meari-native/tests/source_callbacks/host_window.rs). Focused execution covers capacity, synchronous reprojection, last-good rejection, reentrant access and close retry. The OS smoke creates a real surface but supplies synthetic normalized actions; actual OS keyboard/IME, screen-reader and suspend/recreation acceptance remain separate gates. Workspace strict/full regression results must be checked independently of focused test success.

## Typed arrays and keyed string maps

`PropType::Array(Box<PropType>)` and `Value::Array(ArrayValue { element, items })` retain element types, including empty arrays. `ArrayValue::strings` and the Rust runtime's typed `Vec<T>::into_value` preserve all values and order. Type/value depth, aggregate items and UTF-8 byte budgets are checked before binding. `PropType` is now `Clone` rather than `Copy`; consumers must handle its Array variant explicitly. Do not replace real reference arrays with an empty compatibility value.

TSX `string[]`/`Array<T>` and canonical Rust `Vec<T>` roundtrip as typed declarations (output schema8). A plain `props.refs.map(reference => <li key={reference}>{reference}</li>)` retains its source/template/key IR (schema9). The original graph stays source-owned; only runtime projection expands rows. String item keys are unique within their repeat scope. Generated Rust executes the same typed repeat construction. Nested independent array maps preserve outer lexical text and inner binding shadowing.

Keyed component calls preserve their separate state/useId owners through reorder/insert/delete. Native retains DOM NodeIds and migrates widget/input paths by stable IDs. Web prepares insertions and keyed matches, commits its current path map and resolves capture events from the current owned node. Retained editors, focus, dirty uncontrolled input, callback export replacement and deleted-node event lifetimes have execution coverage. Renderer paths change with output order; obtain paths from the current projection rather than storing an index as a lasting row identity.

The current dynamic profile requires a keyed element child list. Mixed positional/static/text siblings, index/record/compound keys and arbitrary item-capturing callbacks need further contracts and adapters. Parent `useId` references retain their original meaning; they are not silently regenerated per row. Reusing that parent ID on multiple DOM elements can reach Native's duplicate-ID diagnostic. Web state-setter input listeners, selection/scroll behavior and actual OS accessibility acceptance remain separate work.

The fixed original Card/Highlight graphs mount with both source references and external actions in Native and Web tests. Native also exposes summary disclosure actions through AccessKit; browser details use native disclosure behavior. Core56, Native20 and desktop in-app browser28 focused tests passed at this checkpoint, with explicit input pins and strict checks recorded privately. These are specified regression scopes, not the full official kitchen-sink or all-platform acceptance result.
