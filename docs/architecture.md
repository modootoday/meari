# Architecture and support boundaries

Meari is a Rust UI framework and Native+Web builder in development. It is maintained in an independent Git repository, intended for consumption through a pinned dependency/submodule. A nested checkout without a registered remote/gitlink is not a completed submodule distribution.

## Dependency direction

`meari` owns portable domain values, source IR, validation and application ports. Parser/code-generation and browser WASM bindings are adapters. `meari-native` depends on the core and owns native CSS/layout/paint/window/file-picker/accessibility adapters. Neither owns consuming-product business policies. CLI and GUI hosts call the same application APIs.

The default workspace build includes only the core. Native engine dependencies are selected explicitly. Web currently uses the core's `wasm` feature; a dedicated Web package will be introduced when DOM/runtime and delivery responsibilities justify it. Package separation does not require immediate independent registry releases.

`meari-native-tools` owns the `meari-native` and `meari-kitchen-sink` executable targets and depends on the native library's existing public entrypoints. Library integration tests select `meari-native`; host CLI/GUI builds select `meari-native-tools`. Executable names, argument handling and application policies are unchanged. The Cargo package selector for running those executables changes to `-p meari-native-tools`. Generated applications continue to depend on the runtime library, not the tools package.

`meari-builder` is the host compiler/CLI package. It loads declared component/config/CSS inputs, verifies registered executable pins and generates applications around a shared `ApplicationDefinition`. Native GUI and headless snapshot/action CLI use the same document factory. Actual Native executable build/render/state/accessibility projection, Web WASM/JS/HTML generation, joint publication and invalid-source last-good preservation have automated integration coverage. Web DOM/platform execution, asset/module delivery and synchronized HMR remain separate acceptance work.

## Source and runtime limits

`application::component_state` provides document/epoch-scoped component instances, parent/key identity, typed state slots and atomic revision-checked action batches. Media bindings use the same state update path. This SDK foundation is available in Native and WASM. Primitive source `useState`/Button setters and Native projection are supported below; general reducers, controlled callbacks and full hook lifecycle remain unfinished.

Conversion preserves a diagnosed subset: string/bool props, bounded single-root `useId`, primitive `useState` declarations, state references and typed Button click setters, source-owned UI elements and source maps. Interleaved `useId`/`useState` declarations preserve their order through explicit hook slots in both frontends. Stateful generated Rust takes an explicit instance snapshot and returns `RenderResult`. Setter expressions support typed scalar arithmetic, strings, strict comparisons, short-circuit logic and conditionals. Free state reads capture the render snapshot; functional updater parameters read the latest state at dispatch. Native persistent documents patch mixed text/disabled state without replacing unrelated inputs. Multi-instance ID/hydration, lazy initializers, general reducers/effects, controlled callbacks, conditions/repeats and arbitrary calls/member expressions remain unfinished and produce diagnostics.

Native widget state and persistent DOM are implemented for selected source-owned contracts. They are not complete upstream React/shadcn provider execution. Full Tailwind/CSS rendering, all widgets, actual OS input and cross-platform accessibility are ongoing acceptance work.

WASM conversion and browser `matchMedia` are implemented. `infrastructure::web_document::WebDocument` mounts a shared `StateProgram` into persistent DOM with owned click listeners, text/attribute patches and a CSS stylesheet. Browser tests cover dirty input/focus retention, mixed text, scoped hook IDs, CSS application and failed dispatch; actual Enter/Space activation is verified in the in-app browser. Default primitive Button/Input lowering is available; complete component recipes/providers, Native/Web parity, build-target/asset bundles and automatic responsive scheduling remain incomplete.

## Revision and resource lifetimes

`application::builder` prepares validated per-target bundles through compiler/input/store ports. Source graphs track content hashes and dependency invalidation; manifests record target/toolchain/settings, source-map bounds and output hashes. Host session/generation guards reject stale results. The local filesystem store writes immutable bundle directories and advances its last-good pointer after all requested targets prepare. Registered Cargo/Trunk adapters generate executable and Web bundles; general asset/module resolution, worker cancellation and incremental runtime delivery remain unfinished.

`domain::host::HostEnvironment` separates layout/visual viewport, device scale, optional observed safe area and supported/unsupported/unknown capabilities. Browser and native window adapters read actual host snapshots; native sizing uses shared CSS measurement policy. `application::screen::resize` tracks one pending request per host and rejects stale or invalid acknowledgements. Native requests distinguish immediate observations from pending OS events. Responsive scheduling, Web preview container resizing and renderer/media/state commit integration remain incomplete.

`application::responsive` applies final renderer environments before evaluating media subscriptions and publishes only successful batches. Failed updates restore the previous renderer/media baseline; failed recovery blocks further publications. Native window size/DPI/theme events use this path, preserving CSS/physical pixel separation and observed document zoom. The observed-host path publishes browser-owned geometry without trying to resize or restore the browser. WebDocument owns coalesced host observations and staged boolean media-state/DOM updates. These Web paths have type-check coverage; their added DOM scenarios still need browser execution. Native media-state integration has execution coverage for viewport changes, retained input/focus/accessibility and failed DOM patch recovery. Web preview, automatic scheduling and source media hooks remain unfinished.

The shared HMR coordinator publishes one revision only after both targets prepare, and accepts synchronized success only after both frame acknowledgements. Failure retains the last common successful publication and requires both rollback acknowledgements. Retained application adapters validate session/target/generation and preserve compatible source state; Native also migrates its existing composite families. Reversible commits preserve a rollback token, retain the latest compatible user state on restoration and reject stale or foreign tokens. A generation high-water mark prevents replay after restoration. Native offscreen frame receipts bind actual pixel hashes to build/state identity. None of these receipts acknowledge an OS-presented frame. Browser editor/source transport, actual two-host frame coordination, CSS/asset replacement and general remount migration remain unfinished. See [runtime lifecycle](runtime-lifecycle.md).

GL contexts/resources belong to native hosts. Context generation, scene revision, component/build revision and asset revision are distinct. Icon cache keys include host/generation, canonical asset hash, resolved style, token specification and scale. Native DLL reload proof, GPU lifecycle proof and integrated Native/Web HMR are separate scopes.

## Verification and publication

Public fixtures and tests are source-owned. Third-party corpora/compiler downloads/hardware tests are explicit external inputs. Passing conversion tests or offscreen rendering does not prove complete Web runtime, visual parity or OS accessibility.

Internal specifications, research and captures stay local. Public source is allowlisted and public main has a separate sanitized history. Private local branches and internal evidence must stay out of later public commits. Executable bundles require dependency/font/asset license review in addition to the project's dual license.
